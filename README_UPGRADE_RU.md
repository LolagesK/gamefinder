# GameFinder PC v0.4.0 — большой каталог Steam в Cloudflare D1

## ВАЖНО: что уже готово и что ещё нужно сделать

Это **готовый исходный код** и GitHub Actions-пайплайн для большого каталога. Сайт в твоём аккаунте НЕ обновлялся автоматически из этого чата. До публикации и запуска Actions в D1 по-прежнему останется столько игр, сколько там было (последняя подтверждённая цифра — 130).

Новый импорт выполняется GitHub Actions на отдельном runner, а не внутри бесплатного Worker. Это существенно надёжнее, потому что Cloudflare Workers Free ограничивает CPU задач по расписанию 10 мс, а большой список Steam требует полноценного разбора JSON. Worker остаётся быстрым сервером поиска и чтения D1.

## Что делает обновление

- GitHub Actions читает `data/game.json` из **неофициального** общедоступного каталога `Austrum-lab/steam-appdb`, где отдельно собраны продукты типа **game**.
- Импортирует до 30 000 *строк источника* в одну задачу (число новых игр может быть меньше), затем продолжает с сохранённого курсора.
- Проверяет AppID и названия, игнорирует записи другого типа, не добавляет дубликаты.
- Использует `INSERT OR IGNORE`, поэтому ранее заполненные 130 карточек и дополнительные сведения Steam **не перезаписываются**.
- Использует Cloudflare D1 REST API с параметризованными запросами и группировкой запросов.
- По умолчанию запускается автоматически раз в сутки, также можно нажать `Run workflow` вручную.
- Worker показывает статус импорта через `/api/catalog/meta` и `/api/catalog/import-status`.
- Поиск в D1 отдаёт по 18 записей за раз; исходный каталог с 130 играми остаётся локальной резервной подборкой.

## Шаг 1 — опубликовать обновление Worker из GitHub

Сейчас GitHub уже подключён к Worker `gamefinder-pc-catalog`, ветка `main`. Cloudflare D1 `gamefinder-catalog` уже создана, переделывать её нельзя и не требуется.

1. Распакуй **GameFinder_PC_v0.4.0_CLOUDFLARE_FULL.zip**.
2. Обнови файлы в репозитории GitHub `LolagesK/gamefinder` с сохранением папок. В особенности:
   - `worker/index.mjs`, `worker/catalog-import.mjs`;
   - `shared/catalog-api.mjs`, `dist/shared/catalog-api.mjs`;
   - `dist/src/main.js`;
   - **новые** `.github/workflows/import-steam.yml` и `scripts/d1-bulk-import.mjs`;
   - `package.json`.
3. **Очень важно:** в `wrangler.jsonc` ZIP находится шаблон `PASTE_DATABASE_UUID_HERE`. Не перезаписывай им уже настроенный `database_id` в GitHub. Проще оставить твой существующий `wrangler.jsonc` без изменений: ни новый cron, ни новая база для v0.4.0 не нужны.
4. Нажми **Commit changes** в `main`. Cloudflare сам запустит деплой через уже настроенную команду `npx wrangler deploy`.
5. Проверь ответ `https://gamefinder-pc-catalog.artem-kostromin-05.workers.dev/api/catalog/meta`. После публикации появится поле `"version":"0.4.0"` и должен сохраниться `"mode":"d1"`.

## Шаг 2 — добавить 3 GitHub Actions secrets (один раз)

Открой GitHub → `LolagesK/gamefinder` → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.

Добавь три секрета:

| Название | Значение (в Github, НЕ отправлять в чат) |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID твоего аккаунта Cloudflare |
| `CLOUDFLARE_D1_ID` | Database ID уже созданной базы `gamefinder-catalog` |
| `CLOUDFLARE_API_TOKEN` | Новый **ограниченный API token** с правом **Account → D1 → Edit** только для нужного аккаунта |

Создать токен можно через Cloudflare → профиль → API Tokens → Create Token → Custom Token. Не используй Global API Key. Храни токен только в секретах GitHub, **никогда не отправляй мне скриншот токена** и не записывай его в `wrangler.jsonc`.

Для Actions нужен API-токен с правом D1 на выбранный аккаунт. Он используется только GitHub runner'ом при загрузке записей и не попадает в сайт или публичные файлы.

## Шаг 3 — запустить первую большую загрузку

GitHub → репозиторий → **Actions** → **Import Steam games to Cloudflare D1** → **Run workflow** → выбери `main` → запусти.

В журнале задачи будет видно, сколько строк обработано. По умолчанию задача повторяется ежедневно в 03:20 UTC. Можно запускать вручную, но не делай много запусков за сутки на бесплатном плане: у D1 лимит 100 000 записанных строк в день на аккаунт.

После успешного запуска открой:

- **Число игр:** `https://gamefinder-pc-catalog.artem-kostromin-05.workers.dev/api/catalog/meta`
- **Прогресс загрузки:** `https://gamefinder-pc-catalog.artem-kostromin-05.workers.dev/api/catalog/import-status`

Примеры:
- `"status":"running", "cursor":30000` — обработана очередная часть списка (но это НЕ значит, что добавилось ровно 30000 уникальных игр).
- `"status":"complete"` — текущая версия списка обработана полностью. Следующая повторная сверка через неделю.

### Когда появятся тысячи игр?

Только **после успешного запуска импорта**. ZIP сам по себе не увеличивает количество записей в D1. Число фактически загруженных игр всегда смотри в `meta.total`.

## Ограничения достоверности

- Источник `Austrum-lab/steam-appdb` — не официальный Steam API. Возможны региональные ограничения, старые названия и неполнота списка. Товары типа DLC/саундтреки отфильтрованы самим источником и дополнительно проверяются импортером при наличии поля `type`.
- У новых игр сначала будут только `Steam AppID` и имя. Цена, оценки, кооператив, размер и требования пока **неизвестны**, а не равны нулю.
- Большие объёмы D1 требуют дальнейшей оптимизации фильтрации под реальную посещаемость: бесплатный лимит чтений 5 млн строк/сутки на аккаунт; CPU обычных запросов Worker ограничен.
- Источник может быть временно недоступен: тогда GitHub Action завершится ошибкой; уже загруженные игры сохраняются.
- Код обогащения цен, оценок и требований **не входит** в этот релиз, пока что основная цель — каталог AppID + названия.

## Безопасность

Работающие сайты и базы удалять не требуется. Скрипт не содержит SQL `DELETE`, `DROP` и не изменяет уже существующие записи каталога. Подключение GitHub и Cloudflare сохраняется.
